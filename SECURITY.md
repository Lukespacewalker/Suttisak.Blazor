# Security Policy

## Reporting a vulnerability

Please do not open a public issue for a suspected vulnerability, exposed credential, authentication weakness, or other security-sensitive report.

Use GitHub Private Vulnerability Reporting for this repository when it is enabled. If that option is not yet available, contact the repository owner privately through their GitHub profile and include only enough information to establish contact; do not publish exploit details or secrets in an issue, pull request, discussion, or commit.

A useful report includes:

- the affected package or component;
- the affected version or commit;
- reproduction steps or a minimal proof of concept;
- the security impact;
- any suggested mitigation, if known.

## Supported versions

Until a formal support matrix is published, security fixes target the latest version on the default branch and the latest package release where practical.

## Credentials

Never commit credentials, tokens, certificates, private keys, production connection strings, or private customer/application configuration to this repository. If a credential is committed, revoke or rotate it immediately even if the commit is later removed from history.
